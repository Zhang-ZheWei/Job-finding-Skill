# S1 岗位采集契约

## 目的

根据 S0 的 `config.json`，依次采集每个“城市筛选 URL × 准确关键词”组合中的岗位卡片。每次只处理一个组合，成功后合并到同一份岗位索引，并保留可恢复的组合检查点。

## 输入与组合计划

- 唯一正式输入是 `{run_root}/job-research-data/config.json`；
- 城市、筛选 URL、关键词、顺序和搜索模式必须由 S0 配置读取；
- 使用 `task_config.py` 生成确定性的组合计划和组合键；
- 只处理检查点中首个未完成组合，不允许模型手填或重排组合；
- 配置哈希不一致、组合不属于计划或结果不属于当前组合时停止。

`exhaustive` 模式自然穷尽所有组合。`per_city_target` 模式采用分批循环：自然穷尽一个组合，完成当前批次 S2 和 S3，再按 `screening-results.json` 中 `status=初筛通过`且 `report_city` 为该城市的唯一岗位数判断是否达标。达到目标后将该城市尚未执行的组合标记为 `skipped_target`；未达到则继续下一个组合。目标数量绝不能使用 S1 原始岗位数、S2 详情数或 S3 总记录数代替。

## 浏览器规则

- 使用 `$web-access` 和已授权的 Chrome 会话。
- 创建一个后台任务标签页，结束后关闭。
- 如果程序滚动失败，只有在已经记录滚动前数量且用户确认手动滚动后，才能读取准确 URL 对应的现有标签页。不得导航、滚动或关闭该用户标签页。
- 只读取 `.job-card-wrap` 岗位卡片。
- 从 `a.job-name` 读取岗位名称和 URL，从 `.boss-name` 读取招聘品牌，从 `.job-salary` 读取薪资，从 `.tag-list li` 读取经验和学历，从 `.company-location` 读取城市。
- 读取首屏后，每次滚动约 2000 像素。
- 每轮保存滚动前后的岗位数、滚动位置、页面高度和新增岗位数。只有页面位置、页面高度、岗位身份或明确结束标志发生可验证变化，才算有效滚动。
- 不论搜索模式，每个实际执行的组合都必须在页面保持正常且连续 10 轮有效增量滚动没有产生新的组合内岗位身份后自然停止。
- 首屏达到 15 条但全部自动滚动都没有产生新岗位，也没有明确结束标志时，返回 `manual_scroll_required`；不得写入岗位索引、完成检查点或 `natural_exhaustion`。
- 出现验证码、安全验证、选择器失效或无效可见卡片时停止。

## 手动滚动续接

- 自动滚动无法证明刷新时，保留采集器创建的唯一搜索标签页，返回 `target_id`、首屏数量、当前数量和滚动证据；
- 用户确认在该标签页完成滚动后，使用同一 `target_id` 继续当前组合；限量验收和正式 `exhaustive` 组合都允许续接；
- 续接时必须验证 URL 与组合一致，并且当前唯一岗位数大于已记录的首屏数量，才能把人工滚动计为成功刷新；
- 用户未确认、目标标签页不一致或滚动后数量没有增长时，继续返回 `manual_scroll_required`，不得猜测完成；
- 读取用户确认的标签页后不得导航、继续替用户操作或关闭该标签页。

## 合并与恢复

- 岗位 ID 和规范化详情 URL 是全局去重依据；
- 同一岗位再次出现时保留原记录，并追加 `source_combinations`、`source_cities` 和 `source_terms`；
- 新岗位按首次发现顺序获得连续的 `first_recall_seq`；
- 每个自然穷尽的组合只保存终态 `completed`；S3 初筛通过数达到城市目标后，未执行组合保存 `skipped_target`及达到目标时的通过岗位键；
- `per_city_target` 每完成一个组合后进入阶段门禁：当前 `job-index.json` 的全部岗位完成 S2 和 S3 前，不得采集下一个组合；
- 中断后重新生成计划，跳过已有终态，只重跑首个没有终态的组合；
- 岗位索引先写、检查点后写。若第二次写入中断，允许重跑同一组合并幂等补齐检查点。

## 输出

`job-index.json` 只保存岗位卡片事实和稳定身份，不得包含 JD、初筛、公司背调、评分、置信度或报告字段。

`checkpoint.json` 保存配置哈希、搜索模式、组合终态和采集证据。采集证据包含人工/自动滚动轮数、成功刷新轮数、逐轮 `scroll_trace` 和结束标志。完整采集的 `sample_limit` 固定为 `null`。所有已执行组合只有满足连续无新增及有效刷新规则时才能写入 `stop_reason=natural_exhaustion`。`skipped_target` 必须保存目标数、当时的 S3 初筛通过数和对应岗位键，证明跳过依据来自 S3。

## 验收条件

独立的单 URL、20 条滚动测试同时满足以下条件时通过采集器验收：

- 准确写入 20 个唯一岗位；
- 首屏唯一岗位少于 20 个；
- 至少发生一次滚动；
- 滚动产生足够的新岗位，使总数达到 20；
- `successful_refresh_rounds` 至少为 1，且逐轮证据能复现岗位数量增长；
- 每条记录的岗位 ID 和规范化详情 URL 一致；
- 验证通过；
- 没有打开岗位详情页。
